# WildPulse Odyssey Agent Guidelines

The following are important system instructions, implementation details, constraints, and historical context about the codebase. Ensure that these are obeyed for all future code modifications and testing.

- Egg visuals (both in canvas animation and inventory slots) dynamically generate a linear gradient reflecting their genetic parentage. This is rendered using a 4-stop gradient mapped from `egg.parentTypes[0]` (father/top color) and `egg.parentTypes[1]` (mother/bottom color) resolved via the `window.TYPE_COLORS` mapping.
- Gamepad D-pad navigation within UI modals (`window.processGamepadInputForPlayer`) uses a 2D spatial navigation algorithm. It calculates distances between elements' bounding boxes prioritizing the `.gamepad-focused-p${playerNum}` class. Specific layered elements like `.custom-color-slider` have explicit 1D linear focus overrides implemented to prevent the 2D bounding box logic from skipping to overlapping UI elements behind them.
- To prevent Phaser Arcade Physics from accumulating massive delta times and causing extreme movement speeds after a browser tab is backgrounded, the Phaser configuration must include `fps: { panicMax: 120 }`.
- Deprecated features: The game no longer supports the 'item wheel', 'pedometer', 'storage chest tile', or the ability for players to place, move, or delete their home in the world. Ensure UI documentation and tutorials omit references to these.
- In `window.finalizeFurnitureTexture`, to simulate 2.5D visual depth when upright furniture is rotated, use `ctx.scale()` (e.g., scaling X to simulate narrower side profiles or mirroring for back views) rather than flat `ctx.rotate()`. Flat objects like carpets should still use standard `ctx.rotate()`.
- To prevent performance drops during heavy weather events in the particle rendering loop, maximum particle counts such as `targetRain` for thunderstorms should be balanced around 60 * window.weatherIntensity.
- The in-game help modal (`helpModal`) follows a cohesive cyberpunk/sci-fi visual design, grouping information under themed uppercase headers (e.g., 'MODULE_01: CONTROL INTERFACE') with neon text borders and dark translucent backgrounds.
- In Playwright tests, co-op mode should be toggled by invoking `window.handleCoopToggle()` or explicitly managed using `window.enableCoop(scene)` and `window.disableCoop(scene)`. The previously assumed `window.toggleCoop()` function does not exist.
- To simulate a battle victory and trigger its subsequent reward UI/logic programmatically in Playwright, configure the battle state (e.g., `window.isNpcBattle = true`, `window.activeBattlePlayer = 1`, `window.currentEnemy = {level: 10}`) and directly call `window.endBattle('win')`.
- Never use native text emojis for UI or item icons; always rely on custom-generated SVGs (e.g., via `window.getItemIconHTML` for items or `window.getCyberpunkIconHTML` for tutorials and notifications) to maintain the cyberpunk aesthetic.
- To simulate realistic ambient wildlife and environments in `window.WildPulseMusic`, `Tone.FMSynth` is used for complex bird chirps, songbirds, doves, warblers, owls, and nightjars. `Tone.MembraneSynth` is used for frogs and woodpeckers, as well as player footsteps (connected directly to `musicBus` to bypass storm reverb masking). `Tone.NoiseSynth` (with 'brown' noise and high-pass filters) is used for crickets, `Tone.Synth` (sawtooth) for crows, and `Tone.MetalSynth` for wind chimes.
- Dynamic weather events and random events are decoupled using `window.activeWeatherEvent` and `window.activeRandomEvent` respectively, allowing them to coexist. Weather updates follow a deterministic cycle with a configurable cooldown (`COOLDOWN_DURATION` of 120,000ms / 2 minutes) in `window.updateRandomEvents`.
- Fallback sell prices for items not listed in the standard store array (e.g., exclusive tiered stat boosters) are determined by the `window.getItemSellPrice(itemName)` function, which parses item prefixes to assign appropriate gold values.
- Co-op proximity visual effects (like the friendship sparkle emitter and pet dancing logic) are triggered when `window.friendshipFrames` exceeds 120. This counter is incremented in the `update()` loop whenever `window.player` and `window.player2` are within 200 pixels (2 tiles) of each other.
- To use raw SVG strings as Phaser textures (like output from `window.getItemIconHTML` or `window.getCreatureTypeIconHTML`), first strip inline `style` attributes to prevent rendering/clipping issues on tightly bound canvases. Then encode the SVG string as a data URI (`data:image/svg+xml;utf8,...`), load it into an HTML `Image` object, draw the image to an HTML Canvas inside the `onload` event, and then register the Canvas with Phaser using `scene.textures.addCanvas()`.
- Dynamic on-screen UI overlays (e.g., `#placementHelpOverlay_p1`) manage contextual control hints by evaluating the active input type, determined via `window['p' + playerNum + 'ActiveInput']` alongside `window.isConsoleOrMobile()`.
- Mini-tile (furniture) placement validation in `window.isValidMiniTileLocation` explicitly restricts placement on 'home_wall', 'home_holo_wall', 'water', and 'tree' tile types.
- In `index.html`, the inventory UI (`updateInventoryList`) must always iterate and render exactly 4 slots (the max items), generating a placeholder `<div class="party-card empty-slot">` element with a dashed border for missing items rather than simply hiding them.
- The game does not feature a mechanical sprinting system; character movement speed is standard, and tutorial text should not reference 'sprint' keys/buttons.
- Furniture sprites spawned in `window.spawnMiniTiles` use a dynamic depth calculation (`10 + (tile.y / 10000)`) to ensure they render correctly in front of static home walls (which are at depth 10), while flat items like carpets remain at a static depth of 8.5.
- For companion pets to successfully spawn in Playwright tests, ensure `window.gameStarted = true` is set (e.g., `if (window.game && window.game.scene.scenes[0]) window.gameStarted = true;`) after manipulating state, allowing the Phaser update loop to process `updatePetFollow`.
- Playwright tests targeting store buttons should locate elements hierarchically (e.g., locate the item container row by text, then find the `.buy-item-btn` class within it) instead of exact `onclick` string matches, as `onclick` attributes are dynamically set to empty strings when items become sold out or unaffordable.
- Gamepad polling logic in the Phaser `update()` loop requires the global `window.cursors` to be initialized directly from `this.input.keyboard.createCursorKeys()` in order to properly detect keyboard activity and assign gamepad focus.
- Storage furniture items (e.g., 'storage_chest', 'furniture_wardrobe') are limited to a maximum of 2 per type per player home. This is enforced during placement in `window.tryPlaceMiniTile` by validating the count within the player's `miniTiles` array, displaying a notification with `window.getLockIconHTML(16)` if exceeded.
- To programmatically simulate gamepad inputs in Playwright tests, mock the global `window.p1PadReference` (or `window.p2PadReference`) object via `page.evaluate()`, providing a `buttons` array where each index corresponds to a button state (e.g., `buttons[4] = { pressed: true }` for the Left Bumper).
- To force the onboarding slides to appear during Playwright tests (overriding the `navigator.webdriver` bypass), set `window.__test_onboarding = true` via `page.add_init_script()`.
- To restrict Phaser sprites or particle emitters (like shooting stars or clouds) to only be visible as reflections on water tiles, set their rendering depth to around 0.05 to 0.06 and apply the global water mask using `.setMask(window.sharedWaterMask)`.
- To prevent severe performance drops from continuous DOM and canvas rebuilding during background state changes (like XP gain or healing), heavy UI rendering functions (such as `window.renderPartyList` and `window.renderStorageList`) must include an early-exit visibility check (e.g., evaluating `modal.style.display === 'block'` or `window.p1ActiveModal`). Furthermore, functions like `renderPartyForPlayer` should implement state caching (e.g., comparing `JSON.stringify(activeParty)`) to skip heavy `innerHTML` rebuilds when the underlying data is unchanged.
- When programmatically testing progress deletion UI flows in Playwright (e.g., `window.deleteProgress`), the `wildpulse_started_once` key must be cached and restored in `sessionStorage` to prevent test-specific initialization scripts from automatically repopulating fallback values and failing null assertions.
- Egg inventory slots in `updatePlayerSlots` use `#ffeb3b` (yellow) for both their default slot border color and the base color of their incubating conic-gradient background to visually differentiate them from standard item slots.
- The `place_furniture` quest type evaluates completion by checking placed tiles directly in `localStorage` (e.g., `wildpulse_p1_mini_tiles`), which inherently allows for retroactive completion if a player placed the furniture before accepting the quest. Additionally, when generating this quest via `generateProceduralQuest`, a `do...while` loop ensures the procedurally generated reward item does not match the target placement item.
- High-tier permanent stat boosters (Uncommon, Rare, Exquisite) and special consumable items (e.g., Cyber-Core Upgrade, Nano-Nurture Serum, DNA Stabilizer, NPC Dual Link, Wild Dual Signal) are obtainable as procedural quest rewards via the `itemsPool` array in `window.generateProceduralQuest`, keeping them out of the standard store.
- To reliably bypass the onboarding modal during Playwright tests and avoid timeouts waiting for the `#startGameBtn`, set `localStorage` items (`wildpulse_has_seen_intro`, `wildpulse_player_color`, `wildpulse_p1_level`, etc.) using `page.add_init_script()` before calling `page.goto()`, ensuring the game state recognizes them immediately on load.
- The main interactive onboarding tutorial (`window.triggerMainTutorial(playerNum)`) is invoked in `window.startGameSession` if `window.isNewGameSession` or `window.needsTutorialTrigger` is true (the latter is set during `closeCustomizationModal` to ensure it fires reliably after setup). It evaluates input methods dynamically across sequential `setTimeout` triggers by checking `window.p1ActiveInput` (or `window.p2ActiveInput` for splitscreen) to adapt the control instructions.
- The introductory onboarding tutorial's display logic uses `localStorage.getItem('wildpulse_has_seen_intro') === 'true'` to ensure it only triggers once per client, independent of the `wildpulse_player_color` save state.
- When mocking Phaser scenes in Playwright tests (e.g., in `tests/newFeatures.spec.js`), `mockScene.add.container` must be mocked to return an object implementing `setDepth`, `add`, `removeAll`, `destroy`, `setData`, and `getData` to support creature nameplate rendering.
- Wild creature levels are dynamically scaled between the player's active party minimum and maximum levels using a deterministic seeded RNG (`sRng()`) in `spawnCreature` and `window.adjustWildCreatureLevels`, except for shiny creatures which default to the party average.
- To allow players to sell items not natively sold in the store (like tiered quest rewards), `window.updateStoreUI` injects the items from the player's inventory into the `activeItems` array with `stock` set to `0`, allowing them to appear in the sell list but remain unpurchasable.
- When exiting a game session to the main menu, use `location.reload()` rather than manual state cleanup to fully reset the WebGL context and prevent black screens or frozen states upon starting a new session.
- The game's UI uses `#00ffcc` (cyan) as the primary theme color for Player 1 elements and `#ff007f` (pink/magenta) for Player 2 elements to clearly separate players and maintain the core cyberpunk aesthetic.
- The storage chest modal (`storageChestModal`) supports localized tile storage (10 slots, using specific `x, y` coordinate parameters) and universal home storage. Universal storage has a base of 5 slots but dynamically expands based on placed storage furniture items (calculated via `window.getHomeStorageMaxSlots`). It is accessed via a button in `#inventoryModal` that is only visible when `window.isPlayerInsideHome(playerNum)` is true, triggered by passing `null` or `undefined` for `tileSprite` coordinates, and saves to `localStorage` using the key `wildpulse_p{playerNum}_home_storage`.
- Frontend visual verification for user-visible changes requires starting the local server (e.g., port 3000), writing a Playwright script to execute the user journey, generating a video and screenshot in `/home/jules/verification/videos` and `/home/jules/verification/screenshots`, and finally calling `frontend_verification_complete`.
- To utilize detailed SVG icons for in-world furniture rather than basic shapes, `generateTileTextures` handles `img.onload` to draw the SVG to a canvas, registers it via `window.finalizeFurnitureTexture`, and iterates through `window.miniTilesGroup` to update existing sprite textures (including rotation variants like '_90').
- To ensure smooth camera and player movement without ground tile jittering, the Phaser rendering configuration in `index.html` must have `roundPixels` set to `false`.
- When triggering rapid or frequent Tone.js synth sounds (such as footsteps or leaves), pass `undefined` instead of `Tone.now()` to `triggerAttackRelease()` to trigger them immediately and prevent Web Audio Context queue buildup or time divergence crashes.
- To ensure specific UI elements (like `.custom-color-slider`, `.custom-color-display`, or dynamically created `.egg-slot` items) are navigable via gamepad D-pad, their specific CSS classes must be explicitly included in the `querySelectorAll` parameter within `window.getNavigableElements` in `index.html`.
- Fireflies are managed by a `FireflyManager` class (instance `window.fireflyEmitter`) whose `.update(dt)` method must be called in the main game loop to process behaviors like sine-wave wandering, player circling, and trails (`blendMode: 'ADD'`). The particles use a procedurally generated 4-frame sprite sheet (`firefly_particles`) defined in `index.html`, with random colors natively selected via the emitter's `frame: [0, 1, 2, 3]` configuration.
- Tiered items (like stat boosters) use prefix-based naming conventions (e.g., 'Uncommon', 'Rare', 'Exquisite'). These string prefixes are parsed during item consumption logic to calculate scaled effects, and in `window.getItemIconHTML` to dynamically assign visual rarity indicators like `glowColor` and `baseColor`.
- For precise orthogonal D-pad UI navigation in `window.processGamepadInputForPlayer`, the spatial scoring algorithm heavily penalizes off-axis elements by multiplying `secondaryDist` by 10. Additionally, analog stick deadzones for movement are set to `0.3` to prevent minor stick drift from overriding D-pad inputs.
- In `window.processGamepadInputForPlayer`, gamepad adjustments for `<input type="range">` elements require holding the 'A' button (`currA`) while pressing D-pad left/right (`currLeft`/`currRight`), adjusting the value by its `step` (respecting `min`/`max`), setting `selectBypass = true` to prevent focus shifting, and explicitly dispatching both `input` and `change` events. For virtual cursor interactions, check `window.p[playerNum]CursorVisible` and `currA`, locate the element via `document.elementFromPoint`, and apply the same adjustment logic.
- In `index.html`, the `window.deleteProgress` function manages game data wipes. It must maintain conditional logic for `localStorage` (a co-op wipe clears everything except `wildpulse_own_world_code` and `wildpulse_world_code`, while a single-player wipe only removes Player 1 specific keys and resets Player 1's NPC trainer data to preserve Player 2). Additionally, it must thoroughly clear `sessionStorage`, the Cache API (`caches`), and IndexedDB (`window.indexedDB.databases()`) databases for both scenarios.
- When implementing dynamic input detection in `index.html` (e.g., switching UI between touch and keyboard controls), mobile browsers commonly fire a synthetic `mousedown` event immediately after `touchstart`. To prevent state flickering, implement a debounce mechanism (e.g., recording `_lastTouchTimeForInput = Date.now()` on `touchstart` and returning early in `mousedown` if `Date.now() - _lastTouchTimeForInput < 500`).
- Modern notifications (`#modernNotification`, `#modernNotification_p2`) use the `.notification-popup` CSS class, which is styled with a cyberpunk aesthetic (neon glows, dark backgrounds, monospace font).
- Update this file every time you do a future update to the game so all information is retained.
- When defining the color slider event listeners inside `window.initCustomColorPicker`, use a standalone initialization function to style the slider backgrounds on load, avoiding dispatching artificial `input` and `change` events which can cause premature data saves and expensive re-rendering.
- When generating dynamic textures using `img.onload` inside `generateTileTextures`, ensure that existing sprites in the scene (like those in `window.miniTilesGroup` or placement preview sprites) have their texture immediately updated (`sprite.setTexture(...)`) to prevent them from remaining as the default missing "green box" placeholder.
- When validating player home bounds, accurately distinguish between the "Home Teleporter" location (the exterior entry point) and the actual 12x12 interior grid map (e.g., `minC = 573, maxC = 585, minR = 573, maxR = 585` for Player 1) to ensure interior-specific queries (like identifying placed furniture) correctly fetch the user's data.
